# Quasimidi TechnoX Lab

A JUCE-based Intel-Mac-oriented reconstruction and reverse-engineering project for the Quasimidi TechnoX. The project builds Audio Unit, VST3 and Standalone formats.

## Implemented and regression-tested

- Original 1200 × 112 SVG front-panel artwork, basic interactive control zones and an LCD-style editor display.
- JUCE 8.0.13 CMake project; Intel x86_64 macOS target with a 10.15 deployment minimum.
- MCS-51/Intel 8032 execution core, timers, MC6850-compatible ACIA MIDI receive path and the TechnoX IC4 v1.05 firmware bus model.
- IC4 ROM address descrambling, IC51 two-bank selection, the firmware-derived resource pointer/descriptor tables and command-stream decoding.
- Factory MIDI/SysEx parsing, 50 factory Performances, lossless 169-byte Performance images and the mapping of the four stored Performance Parts to runtime Parts 13–16.
- Startup decoding of all 512 bank/program resource entries, retaining both firmware-confirmed interpreter flag variants.
- Separate 21-entry FX1 and FX2 directories and their two IC51 upload-stream formats, predecoded for both IC51 banks.
- Byte-exact reconstruction of the 16-KiB C000–FFFF memory image produced by the IC4/IC51 startup transfer.
- Firmware arithmetic models for the recovered lookup tables, 0x1848 fixed-point helper, 0x1EDD parameter path and subsequent slot/modulation coefficient stages.
- A 21-slot voice manager, 16-Part parameter state, Performance/Common and drum stores, MIDI CC/RPN/NRPN routing, and a modulation-matrix framework.
- An interchangeable `IMASSVoiceBackend` interface. The currently audible `BasicMASSVoiceBackend` is a generic test oscillator with per-voice envelope/filter/control behaviour, not the original TechnoX synthesis engine.

The firmware/MIDI regression now also isolates Note On, Note Off, velocity changes, IC51-to-FF10 resource transfers and the four-byte command traffic at XDATA 0x8000–0x8003. See the current verified checkpoint in [`research/ORIGINAL_AUDIO_ENGINE_STATUS.md`](research/ORIGINAL_AUDIO_ENGINE_STATUS.md).

## What is not yet implemented

**The original TechnoX audio engine is not complete.** The current audible sound is generated by the generic test oscillator backend. The external sound processor behind the firmware's command interface has not yet been confirmed, the semantics of its four-byte commands are incomplete, and the IC51 resource bytes have not been decoded into the advertised waveform/sample store. The sample codec, sample address/loop/rate model, original voice algorithms, exact filter/envelope behaviour and original FX DSP are still open work.

The reconstructed 16-KiB C000–FFFF startup image is verified memory plumbing; it must not be mistaken for a complete PCM/sample library. Similarly, the SAM9407 identification remains a hardware-interface hypothesis, not a confirmed chip identification.

## Build on Intel macOS

Install Xcode Command Line Tools and CMake, then run:

```bash
cmake -S . -B build -DCMAKE_OSX_ARCHITECTURES=x86_64 -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

CMake fetches JUCE 8.0.13. The project declares AU, VST3 and Standalone formats and targets macOS 10.15 or later.

## Regression tests

The dependency-free C++17 test targets cover the MCS-51 core, TechnoX 8032 bus/firmware integration, firmware transactions, M.A.S.S. resource ROM parsing, MIDI control routing, Part editing, Performance layers and the generic audio backend. Python tests cover MIDI/SysEx parsing and ROM/disassembly analysis.

- `research/ORIGINAL_AUDIO_ENGINE_STATUS.md` — verified progress, evidence boundaries and next reverse-engineering steps.
- `docs/research/SAM9407_ARCHITECTURE_AND_TECHNOX_BRIDGE.md` — selected SAM9407 architecture target, the separate host/sample-memory domains and evidence required to map IC4 to the chip.
